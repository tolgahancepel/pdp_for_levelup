

Both **`GROUP BY`** and **Window Functions** are SQL features used to aggregate and summarize data, but they serve fundamentally different purposes and solve different types of problems.

Here is a breakdown of when to use each, along with their core use cases.

---

### 1. `GROUP BY` (Aggregation)
**`GROUP BY`** collapses multiple rows into a single summary row per group. 

* **What it does:** Reduces the total number of rows in the result set. If you have 1,000 rows and group by a column with 5 unique values, your output will contain only 5 rows.
* **Key characteristic:** Once you use `GROUP BY`, you lose access to individual row-level details unless they are part of the grouping key or wrapped in an aggregate function (`SUM`, `AVG`, `COUNT`, `MAX`, `MIN`).

#### **Main Use Cases for `GROUP BY`:**
1. **Summarizing data across categories:** Finding total sales, average temperature, or count of users per country/region.
2. **High-level reporting & dashboards:** Generating aggregate metrics (e.g., monthly revenue, total products sold per category).
3. **Filtering aggregated results:** Using the `HAVING` clause to filter groups after aggregation (e.g., "show only categories with total sales greater than $10,000").

* **Example Scenario:** *"What is the total revenue generated by each product category?"*
  ```sql
  SELECT category, SUM(sales_amount) AS total_revenue
  FROM sales
  GROUP BY category;
  ```

---

### 2. Window Functions (Analytical Calculations)
**Window functions** perform calculations across a set of table rows (a "window") that are somehow related to the current row, **without collapsing the rows**.

* **What it does:** Preserves the grain/detail of the individual rows while adding calculated aggregate or positional values as new columns. 
* **Key characteristic:** It uses the `OVER()` clause (often combined with `PARTITION BY` and `ORDER BY`). Every input row remains in the output, accompanied by the result of the window calculation.

#### **Main Use Cases for Window Functions:**
1. **Rankings and Ordering:** Assigning ranks, row numbers, or dense ranks within categories (e.g., top 3 highest-paid employees in each department).
2. **Running Totals and Moving Averages:** Calculating cumulative sums or rolling averages over time without losing daily transaction details.
3. **Comparing a row to adjacent rows:** Accessing previous or next row values using `LAG()` and `LEAD()` (e.g., calculating month-over-month growth or finding time gaps between user logins).
4. **Partitioned Aggregates:** Displaying an aggregate metric (like department average salary) alongside every individual employee's record so you can compare them (e.g., finding employees who earn *more* than their department average).

* **Example Scenario:** *"Show every employee's salary alongside the average salary of their department."*
  ```sql
  SELECT 
      employee_name, 
      department, 
      salary,
      AVG(salary) OVER(PARTITION BY department) AS dept_avg_salary
  FROM employees;
  ```

---

### Quick Comparison Summary

| Feature | `GROUP BY` | Window Functions (`OVER`) |
| :--- | :--- | :--- |
| **Row Count** | **Reduces** rows (collapses data into summary groups). | **Preserves** all original rows. |
| **Output Grain** | Group level (one row per group). | Detail level (one row per original record). |
| **Access to Details** | Lost (you cannot see individual row data inside a group). | Retained (individual rows remain visible alongside the calculation). |
| **Primary Clause** | `GROUP BY` | `OVER (PARTITION BY ... ORDER BY ...)` |
| **Typical Functions** | `SUM`, `AVG`, `COUNT`, `MAX`, `MIN` | `ROW_NUMBER()`, `RANK()`, `SUM()`, `AVG()`, `LAG()`, `LEAD()` |

### Rule of Thumb
* Use **`GROUP BY`** when you want to **condense** your data to see the big picture (e.g., *"Give me total sales per store"*).
* Use **Window Functions** when you want to **keep the details** while adding contextual calculations or rankings (e.g., *"Give me every sale, but also show how it ranks against other sales in the same store"*).
